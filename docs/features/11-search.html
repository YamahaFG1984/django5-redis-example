Step 11 · 列表与字典序

搜索增强：热搜榜、搜索历史、前缀联想

给原书的搜索页加上三个常见功能：热搜榜（ZSET 计数）、个人最近搜索（LIST 加去重和截断），以及输入时的标题联想（利用 ZSET 在分数相同时按字典序排列的特性做前缀查询）。

本章目标

  • 用 ZSET 统计热搜词
  • 用 LIST 的 LREM + LPUSH + LTRIM 维护最近搜索
  • 用 ZRANGEBYLEX 实现前缀联想

关键词先规范化：小写、合并空白。
✓ LREM 的复杂度

LREM 是 O(N)，要遍历整个列表。因为有 LTRIM，列表长度始终不超过 10，所以没有问题。如果列表很长又需要去重，应该换成 ZSET（member = 关键词，score = 时间戳）。

标题联想：ZRANGEBYLEX

原理

当 ZSET 中所有元素的 score 相同时，元素按 member 的字节序排列。这时就可以用 ZRANGEBYLEX key [min [max 按字符串范围查询。「以 redis str 开头」等价于「≥ redis str 且 ≤ redis str + 一个最大的字符」：

member 的格式是 小写标题|文章ID：前半部分用于排序和匹配，后半部分用于取回文章。

上界为什么用 U+10FFFF

常见的写法是用 \xff 作为上界。在 Python 中，'\xff' 是字符 ÿ，用 UTF-8 编码后是 C3 BF 两个字节。而中文字符的 UTF-8 编码以 E4~E9 开头，比 C3 大，所以 redis 入门 会排在上界 redis ÿ 之后，查不到。U+10FFFF 是 Unicode 的最大码点，编码为 F4 8F BF BF，比任何合法的 UTF-8 字符都大。测试 test_non_ascii_titles 覆盖了这个情况。

ⓘ 另一种做法

如果 redis-py 不设置 decode_responses，可以直接用字节 b'\xff' 作为上界（0xFF 不会出现在合法的 UTF-8 中）。本项目统一用 str，所以选了 U+10FFFF。

维护索引

# ---------------------------------------------------------------- step-11 搜索
def search_hot():
    """ZSET  热搜词：member = 规范化后的关键词，score = 搜索次数"""
    return _k('search', 'hot')


def search_history(visitor_id):
    """LIST  访客最近的 10 条搜索，最新的在最左边，TTL 30 天"""
    return _k('search', 'history', visitor_id)


def search_suggest():
    """ZSET  标题联想索引：score 全为 0，member = "小写标题|文章 ID"，按字典序排列"""
    return _k('search', 'suggest')

代码实现

def record_search(visitor_id, query):
    q = normalize(query)
    if not q:
        return
    history = K.search_history(visitor_id)
    pipe = get_redis().pipeline()
    pipe.zincrby(K.search_hot(), 1, q)
    pipe.lrem(history, 0, q)              # 先删掉旧的同名记录（去重）
    pipe.lpush(history, q)                # 插到最前面
    pipe.ltrim(history, 0, HISTORY_SIZE - 1)  # 只保留最近 10 条
    pipe.expire(history, HISTORY_TTL)
    pipe.execute()
def index_title(post, old=None):
    """文章保存时维护联想索引。old 是修改前的文章（标题可能变了）。"""
    pipe = get_redis().pipeline()
    if old is not None:
        pipe.zrem(K.search_suggest(), _member(old))
    if post.status == Post.Status.PUBLISHED:
        pipe.zadd(K.search_suggest(), {_member(post): 0})
    else:
        pipe.zrem(K.search_suggest(), _member(post))
    pipe.execute()
def suggest(prefix, limit=SUGGEST_LIMIT):
    """返回标题以 prefix 开头的已发布文章。"""
    p = normalize(prefix)
    if not p:
        return []
    # 所有 score 相同时，ZSET 按 member 的字节序排列，[ 表示闭区间
    members = get_redis().zrangebylex(
        K.search_suggest(), f'[{p}', f'[{p}{MAX_CHAR}', start=0, num=limit
    )
    ids = [int(m.rsplit(SEP, 1)[1]) for m in members]
    posts = Post.published.in_bulk(ids)
    return [posts[i] for i in ids if i in posts]
def search_suggest(request):
    posts = search.suggest(request.GET.get('q', ''))
    return JsonResponse(
        [{'title': p.title, 'url': p.get_absolute_url()} for p in posts],
        safe=False,
    )

动手实验

  1. 执行 python manage.py rebuild_redis_index，为已有文章建立联想索引。
  2. 打开 /blog/search/，在输入框中输入 re、redis s、dj，观察下方的联想结果。
  3. 分别搜索 Redis、redis、Django，回到搜索页，查看「最近搜索」和「热搜」。

  4. 在 redis-cli 中：

    > ZRANGE blog:search:suggest 0 -1
> ZREVRANGE blog:search:hot 0 9 WITHSCORES
> LRANGE blog:search:history:s:<sessionid> 0 -1
  5. 在 Admin 中修改一篇文章的标题，再测试联想，旧标题已经搜不到了。

边界与思考

⚠ 本实现的取舍
  • 只能匹配开头：输入 orm 找不到 Django ORM Tips。可以把标题的每个单词开头都作为一个 member 加进去（orm tips|3、tips|3），代价是索引变大。
  • 热搜没有过滤：任何人都能刷热搜词。实际应用中要配合限流（第 10 章）和敏感词过滤，也可以只统计有搜索结果的词。
  • 热搜没有时间维度：可以参照第 4 章，按天拆 Key，再用 ZUNIONSTORE 合并出「近 7 天热搜」。
