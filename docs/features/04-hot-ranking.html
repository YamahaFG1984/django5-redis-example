Step 04 · 有序集合

热门排行榜：总榜、日榜、周榜

排行榜是有序集合（ZSET）最常见的用途。这一章用 ZINCRBY 实时累加热度，用 ZREVRANGE 取前 N 名，用按天拆分的 Key 加 ZUNIONSTORE 实现「最近 7 天」的周榜。

git checkout step-04-hot-ranking ZSET

本章目标

  • 理解 ZSET 的跳表 + 哈希表结构
  • 用 ZINCRBY / ZREVRANGE 实现实时榜单
  • 用按天拆分的 Key 加 ZUNIONSTORE 实现周榜
  • 用信号让榜单和数据库保持一致

场景分析

PRD F2 要求：侧边栏展示本周热门前 5，/blog/ranking/ 页面展示今日、近 7 天、总榜前 10，热度实时更新，下线的文章不能出现在榜单里。

用 SQL 怎么做

  • 总榜：ORDER BY views DESC LIMIT 10。需要在 views 上建索引，而 views 每次浏览都在变，索引维护成本高。
  • 日榜 / 周榜：需要一张「浏览日志」表，每次浏览插入一行，查询时 WHERE date >= ... GROUP BY post_id ORDER BY COUNT(*)。数据量越大越慢。

排行榜的特点是更新频繁、读取频繁、只关心前几名，适合用 ZSET。

ZSET 是怎么实现的

ZSET 中每个元素（member）带一个分数（score），按分数排序。内部同时维护两种结构：哈希表用于按 member 查 score（O(1)），跳表用于按分数排序和范围查询（O(log N)）。

命令作用复杂度本章用途
ZINCRBY key n member给 member 的分数加 n，member 不存在时自动创建O(log N)热度 +1
ZREVRANGE key 0 9 WITHSCORES分数从高到低取第 1~10 名O(log N + M)取榜单
ZUNIONSTORE dest k key1 … keyk多个集合求并集，同一 member 的分数相加，结果写入 destO(N) + O(M log M)7 天合并成周榜
ZREM key member删除元素O(log N)下线文章
ZREVRANK key member查名次O(log N)（扩展）显示「第 3 名」

Key 设计

日榜、周榜通过 按天拆分 Key 实现：每天一个 ZSET，Key 里带日期。查询某天的数据直接读对应的 Key，过期数据由 TTL 自动清理。

周榜是怎么合并的

✓ 为什么周榜要缓存

ZUNIONSTORE 的复杂度和所有输入集合的元素总数成正比。每个请求都执行一遍没有必要，周榜晚 5 分钟更新完全可以接受，所以把结果写进带 TTL 的 Key，过期后再重新计算。

Key

# ---------------------------------------------------------------- step-04 排行榜
def rank_total():
    """ZSET  总榜：member = 文章 ID，score = 浏览次数"""
    return _k('rank', 'views', 'total')


def rank_daily(day):
    """ZSET  日榜，TTL 8 天"""
    return _k('rank', 'views', 'day', day.strftime('%Y%m%d'))


def rank_weekly(day):
    """ZSET  截止到 day 的 7 天榜（7 个日榜的并集），缓存 5 分钟"""
    return _k('rank', 'views', 'week', day.strftime('%Y%m%d'))

写入热度

def record_view(post_id, day=None, amount=1):
    """文章热度 +amount：总榜和当天的日榜同时累加。"""
    day = day or timezone.localdate()
    daily = K.rank_daily(day)
    pipe = get_redis().pipeline()
    pipe.zincrby(K.rank_total(), amount, post_id)
    pipe.zincrby(daily, amount, post_id)
    # 每次都刷新过期时间也没关系：日榜最后一次写入后 8 天被删除
    pipe.expire(daily, DAILY_TTL)
    pipe.execute()

合并周榜

def _weekly_key(today):
    """把最近 7 天的日榜合并成周榜。结果缓存 5 分钟，避免每次请求都重新合并。"""
    r = get_redis()
    key = K.rank_weekly(today)
    if not r.exists(key):
        days = [K.rank_daily(today - timedelta(days=i)) for i in range(7)]
        pipe = r.pipeline()
        # 同一篇文章在多个日榜中的 score 相加（默认 AGGREGATE SUM）
        pipe.zunionstore(key, days)
        pipe.expire(key, WEEKLY_CACHE_SECONDS)
        pipe.execute()
    return key

读取榜单

def top_posts(period='total', count=10, today=None):
    """返回已发布的热门文章列表，每篇文章带上 score 属性。"""
    # 多取一些，防止榜单里有已下线的文章导致数量不够
    pairs = top_ids(period, count * 2, today)
    posts = Post.published.in_bulk([post_id for post_id, _ in pairs])
    result = []
    for post_id, score in pairs:
        post = posts.get(post_id)
        if post is not None:
            post.score = score
            result.append(post)
    return result[:count]

in_bulk() 一条 SQL 取出所有文章并返回 {id: post} 字典，再按 Redis 给出的顺序组装列表。Post.published 管理器保证下线的文章不会出现。

边界与思考

⚠ 本实现的取舍
  • 周榜有最多 5 分钟的延迟：日榜、总榜是实时的。
  • 分数相同时的排序：ZSET 中分数相同的元素按 member 的字典序排列，ZREVRANGE 则是字典序倒序。如果希望「先达到这个分数的排在前面」，可以把时间编码进分数，例如 score = 热度 + (1 - 时间戳/1e10)。
  • 日期按 TIME_ZONE 计算：项目设置为 UTC，所以「今天」从北京时间 8 点开始算。改成 Asia/Shanghai 即可。
