Step 09 · 集合运算

个性化推荐：兴趣画像 × 标签倒排 × 加权并集

不需要机器学习，用 Redis 的集合运算就能做一个可用的基于内容的推荐：读过什么标签就记下兴趣，按兴趣分给标签下的文章加权求和，去掉读过的，不够再用热榜补齐。整个计算在 Redis 内部用 3 条命令完成。

git checkout step-09-recommend ZSETSET

本章目标

  • 用 SET 建立「标签 → 文章」倒排索引
  • 用 ZSET 维护访客兴趣画像
  • 用加权 ZUNIONSTORE + ZDIFFSTORE 计算推荐
  • 处理冷启动和推荐结果缓存

场景分析

PRD F7：根据读过文章的标签推荐相关文章；不推荐已读的；新访客用热榜补齐；结果缓存 60 秒。

原书第 3 章的「相似文章」是按当前这一篇文章的标签用 SQL 计算的（Count('tags')），只和当前文章有关，与读者是谁无关。个性化推荐需要考虑读者的全部阅读历史，用 SQL 做要关联阅读日志、文章、标签三张表，每个请求都算一遍代价太高。

ⓘ SET 也能参与 ZUNIONSTORE

ZUNIONSTORE、ZINTERSTORE、ZDIFFSTORE 的输入可以是普通 SET，SET 中每个元素的 score 视为 1。乘上 WEIGHTS 中对应的权重，就是「这个标签的兴趣分」。所以倒排索引用 SET 就够了，不需要额外存分数。

def tag_posts(tag_slug):
    """SET  倒排索引：标签 → 已发布文章 ID"""
    return _k('tag', tag_slug, 'posts')


def post_tags(post_id):
    """SET  正排：文章 → 标签 slug，用来计算标签的增删"""
    return _k('post', post_id, 'tags')


def visitor_interests(visitor_id):
    """ZSET  兴趣画像：member = 标签 slug，score = 读过的该标签文章数，TTL 30 天"""
    return _k('visitor', visitor_id, 'interests')


def visitor_read(visitor_id):
    """SET  读过的文章 ID，TTL 30 天"""
    return _k('visitor', visitor_id, 'read')


def recommend_result(visitor_id):
    """ZSET  推荐结果缓存：member = 文章 ID，score = 推荐分，TTL 60 秒"""
    return _k('recommend', visitor_id)

倒排索引

def _sync_index(post_id, new_tags):
    r = get_redis()
    old_tags = r.smembers(K.post_tags(post_id))
    pipe = r.pipeline()
    for slug in old_tags - new_tags:
        pipe.srem(K.tag_posts(slug), post_id)
    for slug in new_tags - old_tags:
        pipe.sadd(K.tag_posts(slug), post_id)
    pipe.delete(K.post_tags(post_id))
    if new_tags:
        pipe.sadd(K.post_tags(post_id), *new_tags)
    pipe.execute()

记录阅读

def record_read(visitor_id, post_id):
    """记录一次阅读：更新兴趣画像和已读集合，并让旧的推荐结果失效。"""
    r = get_redis()
    tags = r.smembers(K.post_tags(post_id))   # 直接从 Redis 取标签，不查数据库
    interests = K.visitor_interests(visitor_id)
    read = K.visitor_read(visitor_id)
    pipe = r.pipeline()
    for slug in tags:
        pipe.zincrby(interests, 1, slug)
    pipe.sadd(read, post_id)
    pipe.expire(interests, PROFILE_TTL)
    pipe.expire(read, PROFILE_TTL)
    pipe.delete(K.recommend_result(visitor_id))
    pipe.execute()

计算推荐

def _compute(r, visitor_id):
    """用兴趣最高的标签计算推荐结果，写入 blog:recommend:{vid}。"""
    result = K.recommend_result(visitor_id)
    tags = top_interests(visitor_id)
    if not tags:
        return
    pipe = r.pipeline()
    # 加权并集：一篇文章的分 = 它所属的每个标签的兴趣分之和
    # （SET 作为 ZUNIONSTORE 的输入时，每个元素的 score 视为 1）
    pipe.zunionstore(result, {K.tag_posts(slug): score for slug, score in tags})
    # 差集：去掉读过的文章（ZDIFFSTORE 也接受普通 SET 作为输入）
    pipe.zdiffstore(result, [result, K.visitor_read(visitor_id)])
    pipe.expire(result, RESULT_TTL)
    pipe.execute()
def recommend_ids(visitor_id, count=5):
    r = get_redis()
    result = K.recommend_result(visitor_id)
    if not r.exists(result):
        _compute(r, visitor_id)
    ids = [int(m) for m in r.zrevrange(result, 0, count - 1)]

    if len(ids) < count:
        # 冷启动 / 兴趣标签下的文章都读完了：用总榜补齐
        candidates = [
            post_id for post_id, _ in ranking.top_ids('total', count * 3)
            if post_id not in ids
        ]
        if candidates:
            already_read = r.smismember(K.visitor_read(visitor_id), candidates)
            ids += [
                post_id for post_id, seen in zip(candidates, already_read) if not seen
            ][: count - len(ids)]
    return ids

边界与思考

⚠ 本实现的取舍
  • 兴趣不会衰减：一个月前读的和今天读的权重一样，只有 30 天不访问才整体过期。可以定期把所有分数乘以 0.9（ZUNIONSTORE 单个输入时配合 WEIGHTS 0.9），或者把时间编码进分数。
  • 热门标签占优：标签下文章越多，命中越多。可以按 TF-IDF 的思路，用「标签下文章数」的倒数调整权重。
  • 每次阅读都会让缓存失效：一个访客连续阅读时，每次都要重新计算。计算量很小（只涉及几个集合），如果标签集合很大，可以不在阅读时删除缓存，而是等 TTL 过期。
