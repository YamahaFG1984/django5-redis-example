文章浏览量：PV、UV 与防刷

文章页显示「123 次浏览 · 45 位读者」。这个需求涉及 Redis 的几个常见用法：原子计数、带过期时间的去重标记、HyperLogLog 基数统计，以及先写 Redis 再定时回写数据库。

本章目标

  • 用 INCR 实现原子计数

场景分析

需求回顾（PRD F1）

  • 详情页显示 PV（浏览次数）和 UV（独立读者数），列表页显示每篇的 PV；
  • 同一访客 30 分钟内刷新只算 1 次；
  • 浏览量要落到数据库，Redis 数据丢了也不能归零。

只用数据库会有什么问题

最直接的写法是每次打开文章执行 UPDATE blog_post SET views = views + 1 WHERE id = 42，问题有三个：

  1. 行锁争用：热门文章的所有并发请求都要更新同一行，只能排队。
  2. 读请求变成了写请求：看文章本来只需要读，现在每次都要写日志、刷盘。
  3. 去重和 UV 难做：要判断「这个人 30 分钟内看过没有」，需要再建一张访问记录表。

UV 去重统计用什么

UV 就是「有多少个不同的人看过」，也就是集合的基数。假设一篇爆款文章有 100 万访客：

方案内存（100 万访客）准确度能否知道某人看过没有
SET 存所有访客 ID约 60~90 MB（Session key 32 字节 + 元素开销）精确能，SISMEMBER
BITMAP（offset = 用户 ID）约 125 KB（ID 最大到 100 万）精确能，但只适用于整数 ID，匿名访客没法用
✓ HyperLogLog固定 12 KB标准误差 0.81%不能

UV 只用来展示，不需要精确，也不需要判断某个人是否看过，所以选 HyperLogLog。

ⓘ 直观理解

连抛硬币，如果你说「我最多一次连续抛出了 10 个反面」，别人可以推测你大概抛了 210 轮左右。HyperLogLog 的估算思路与此类似，再用 16384 个桶取平均来降低误差。

防刷：30 分钟内只算一次

每个「文章 + 访客」组合对应一个带 30 分钟 TTL 的标记。SET key 1 NX EX 1800 一条命令同时完成「判断是否存在」和「写入并设置过期」，并且是原子的：

✗ 不要这样写（有竞态）
if not r.exists(key):      # 两个请求可能同时判断为不存在
    r.set(key, 1, ex=1800)
    r.incr(views_key)      # 结果计了两次
✓ 应该这样写（原子）
if r.set(key, 1, nx=True, ex=1800):
    r.incr(views_key)
# NX：不存在才写，返回 True / None
# EX：1800 秒后自动删除

def post_views(post_id):
    """STRING  文章 PV 计数"""
    return _k('post', post_id, 'views')


def post_uv(post_id):
    """HYPERLOGLOG  文章 UV（独立访客数）"""
    return _k('post', post_id, 'uv')


def post_seen(post_id, visitor_id):
    """STRING  防刷标记：某访客最近看过某文章，TTL 30 分钟"""
    return _k('post', post_id, 'seen', visitor_id)


def post_views_dirty():
    """SET  浏览量有变化、等待回写数据库的文章 ID"""
    return _k('post', 'views', 'dirty')

代码实现

访客标识

def get_visitor_id(request):
    """
    返回当前访客的唯一标识，供浏览量、推荐、搜索历史等功能使用。

    已登录用户：u:{用户ID}，换设备也是同一个人
    匿名访客：  s:{session_key}，第一次访问时创建 Session
    """
    if request.user.is_authenticated:
        return f'u:{request.user.pk}'
    if not request.session.session_key:
        request.session.save()
    return f's:{request.session.session_key}'

记录浏览

def record_view(post, visitor_id):
    """记录一次浏览。返回 True 表示计入了 PV，False 表示被防刷规则过滤。"""
    r = get_redis()
    # 1. 防刷：SET NX 只在 key 不存在时写入成功，EX 让标记 30 分钟后自动消失
    first_visit = r.set(
        K.post_seen(post.id, visitor_id), 1, nx=True, ex=DEDUP_SECONDS
    )
    if not first_visit:
        return False

    # 2. 剩下的命令打包成一个 pipeline，一次网络往返全部发出去
    pipe = r.pipeline()
    # Redis 里还没有计数（第一次访问，或 Redis 数据丢失）时，用数据库里的值打底
    pipe.set(K.post_views(post.id), post.views, nx=True)
    pipe.incr(K.post_views(post.id))
    pipe.pfadd(K.post_uv(post.id), visitor_id)
    # 记下这篇文章需要回写数据库
    pipe.sadd(K.post_views_dirty(), post.id)
    pipe.execute()
    return True
★ 为什么要先 SET NX 再 INCR？

假设数据库里已经存了 views = 5000，而 Redis 重启后数据丢了。如果直接 INCR，计数会从 1 开始。先执行 SET key 5000 NX：key 不存在时写入 5000，存在时什么也不做。这两条命令放在同一个 MULTI/EXEC 事务里，中间不会插入其他客户端的命令。

批量读取

def attach_view_counts(posts):
    """给一组文章批量设置 view_count 属性：只用一次 MGET，而不是 N 次 GET。"""
    posts = list(posts)
    if not posts:
        return posts
    values = get_redis().mget([K.post_views(p.id) for p in posts])
    for post, value in zip(posts, values):
        post.view_count = int(value) if value is not None else post.views
    return posts

回写数据库

def sync_views_to_db(batch_size=500):
    """把 Redis 中的浏览量回写到 Post.views，返回更新的文章数。"""
    r = get_redis()
    updated = 0
    while True:
        # SPOP 随机弹出一批 ID：弹出即删除，多个进程同时执行也不会重复处理
        ids = r.spop(K.post_views_dirty(), batch_size)
        if not ids:
            break
        values = r.mget([K.post_views(post_id) for post_id in ids])
        posts = [
            Post(id=int(post_id), views=int(value))
            for post_id, value in zip(ids, values)
            if value is not None
        ]
        Post.objects.bulk_update(posts, ['views'])
        updated += len(posts)
    return updated

模型上新增了 views 字段（迁移 0006_post_views），保存的是 Redis 计数的持久化副本。

动手实验

  1. 打开一篇文章，刷新几次，确认浏览数没有增加；换一个浏览器（或无痕窗口）打开，浏览数 +1，读者数 +1。

  2. 观察 Redis：

    $ docker compose exec redis redis-cli --scan --pattern 'blog:post:*'
$ docker compose exec redis redis-cli TTL blog:post:1:seen:s:<你的 session key>

  3. 回写数据库，然后在 Admin 的文章列表里查看 views 列：

    $ python manage.py sync_post_views
Synced views for 3 post(s).

  4. 模拟 Redis 数据丢失：执行 FLUSHDB 后再访问文章，浏览量从数据库里的值继续 +1，不会从 1 开始。

边界与思考

⚠ 已知的取舍
  • SPOP 之后进程崩溃：这批 ID 已经从 dirty 集合删除，但还没写入数据库。计数仍然在 Redis 里，下次这些文章被访问时会重新加入 dirty 集合。如果需要严格保证，可以改用 SMOVE 移到一个 processing 集合，写库成功后再删除。
  • 爬虫会创建大量 Session：每个匿名访客都会在数据库里生成一条 Session 记录。生产环境可以先按 User-Agent 过滤爬虫，或者改用 IP + UA 的哈希作为访客 ID。
  • UV 有约 0.81% 的误差：展示用没问题，计费、结算这类场景不能用。
