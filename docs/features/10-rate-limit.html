Step 10 · Lua 脚本

接口限流：固定窗口、滑动窗口与 Lua 原子性

评论和分享邮件接口不能被脚本刷。这一章实现两种限流算法：固定窗口（STRING 计数）和滑动窗口（ZSET 记录每次请求的时间），用 Lua 脚本保证「判断 + 计数」是原子操作，再封装成一个视图装饰器。

git checkout step-10-rate-limit STRINGZSETLUA

本章目标

  • 理解固定窗口和滑动窗口的区别，以及窗口边界问题
  • 用 Lua 脚本把「判断 + 计数」变成原子操作
  • 理解 EVALSHA 和脚本缓存
  • 把限流封装成视图装饰器

场景分析

接口风险规则（PRD F8）算法
POST /blog/<id>/comment/垃圾评论刷屏每 IP 每分钟 3 条滑动窗口（要求精确）
POST /blog/<id>/share/被用来群发邮件、消耗 SMTP 配额每 IP 每小时 5 封固定窗口（够用，开销最小）

限流计数必须放在所有 Web 进程都能访问的地方。每个 gunicorn worker 自己在内存里计数的话，开 4 个进程，实际限额就变成了 4 倍。Redis 正适合做这种共享计数。

两种算法

固定窗口

把时间切成固定长度的窗口（比如每分钟一个），每个窗口一个计数器：INCR blog:ratelimit:fixed:comment:1.2.3.4:{分钟序号}，超过上限就拒绝，窗口结束后计数器自然过期。

滑动窗口

用 ZSET 记录每一次请求的时间戳。每次请求先删掉「当前时间 - 窗口长度」之前的记录，再数剩下多少条。窗口跟着当前时间移动，没有固定的边界。

算法Redis 结构内存精确度备注
固定窗口STRING 计数器每个 IP 一个整数边界处最多 2 倍最简单
滑动窗口日志ZSET每个 IP 最多 limit 条记录精确limit 很大时（比如每小时 1 万次）内存开销大
滑动窗口计数两个 STRING每个 IP 两个整数近似用上一窗口计数 × 重叠比例估算
令牌桶HASH（令牌数、上次时间）每个 IP 两个字段精确，允许突发思考题

代码实现

固定窗口

def fixed_window(scope, ident, limit, window, now=None):
    now = time.time() if now is None else now
    window_index = int(now // window)
    count = _run(
        FIXED_WINDOW_SCRIPT,
        [K.ratelimit_fixed(scope, ident, window_index)],
        [window],
    )
    if count <= limit:
        return Decision(True, limit - count, 0)
    window_end = (window_index + 1) * window
    return Decision(False, 0, int(window_end - now) + 1)

滑动窗口

local now = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local limit = tonumber(ARGV[3])
-- 1. 删掉已经滑出窗口的请求记录
redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', now - window)
-- 2. 窗口内还有名额：记下这次请求
if redis.call('ZCARD', KEYS[1]) < limit then
    redis.call('ZADD', KEYS[1], now, ARGV[4])
    redis.call('PEXPIRE', KEYS[1], window)
    return {1, limit - redis.call('ZCARD', KEYS[1]), 0}
end
-- 3. 没有名额：最早的那条记录滑出窗口后才能再请求
local oldest = redis.call('ZRANGE', KEYS[1], 0, 0, 'WITHSCORES')
return {0, 0, tonumber(oldest[2]) + window - now}
def sliding_window(scope, ident, limit, window, now=None):
    now_ms = int((time.time() if now is None else now) * 1000)
    allowed, remaining, retry_ms = _run(
        SLIDING_WINDOW_SCRIPT,
        [K.ratelimit_sliding(scope, ident)],
        # 每个请求一个唯一 member，避免同一毫秒的两次请求互相覆盖
        [now_ms, window * 1000, limit, f'{now_ms}-{uuid.uuid4().hex[:8]}'],
    )
    return Decision(bool(allowed), remaining, -(-retry_ms // 1000))  # 向上取整
ⓘ 为什么当前时间由 Python 传入

Lua 脚本里也可以调用 redis.call('TIME') 取 Redis 服务器的时间，这样多台 Web 服务器的时钟不一致也没关系。这里由调用方传入 now，是为了让测试可以精确模拟「59 秒」「61 秒」等时刻。

装饰器

def rate_limit(scope, limit, window, algorithm='sliding', methods=('POST',)):
    """视图装饰器：同一 IP 在 window 秒内最多请求 limit 次，超出返回 429。"""
    check = sliding_window if algorithm == 'sliding' else fixed_window

    def decorator(view):
        @wraps(view)
        def wrapper(request, *args, **kwargs):
            if request.method in methods:
                decision = check(scope, client_ip(request), limit, window)
                if not decision.allowed:
                    response = render(
                        request,
                        'blog/rate_limited.html',
                        {'retry_after': decision.retry_after},
                        status=429,
                    )
                    response['Retry-After'] = str(decision.retry_after)
                    return response
            return view(request, *args, **kwargs)

        return wrapper

    return decorator
@require_POST
# Redis: at most 3 comments per IP per minute (sliding window)
@rate_limit('comment', limit=3, window=60, algorithm='sliding')
def post_comment(request, post_id):
    ...

# Redis: at most 5 share emails per IP per hour (fixed window)
@rate_limit('share', limit=5, window=3600, algorithm='fixed')
def post_share(request, post_id):
    ...

边界与思考

⚠ 本实现的取舍
  • 按 IP 限流：同一个公司或学校的用户可能共用一个出口 IP。登录用户可以改为按用户 ID 限流。
  • 部署在反向代理后面时，REMOTE_ADDR 是代理的地址，需要从可信代理设置的 X-Forwarded-For 中取真实 IP；不能直接相信客户端传来的这个头，否则可以伪造。
  • Lua 脚本会阻塞 Redis：脚本要短小，不能在里面遍历大集合。
  • Redis Cluster 中，脚本访问的所有 Key 必须在同一个 slot。本章每个脚本只操作一个 Key，没有这个问题。
