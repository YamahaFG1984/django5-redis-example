怎么用这份文档

建议按下面的顺序读：先看 PRD 和设计文档了解全局，然后每读完一章就 git checkout 到对应的 tag，把代码跑起来，再用 redis-cli 看看 Redis 里到底存了什么。

每一章的结构都一样：

  1. 场景分析：业务上要解决什么问题，只用数据库为什么不够好。
  2. 方案选型：把几种 Redis 数据结构放在一起比较，说明为什么选这一种。
  3. Key 设计：用卡片画出 Redis 里实际存的内容。
  4. 流程图：一次请求里 Django 和 Redis 是怎么交互的。
  5. 代码实现：文档里的代码由 docs/tools/sync_code.py 从源码同步，和仓库里完全一致。
  6. 动手实验与思考题：用 redis-cli 验证，再想想边界情况。

快速开始

# 1. 启动 Postgres + Redis + Django + 通知 worker
$ cd Chapter03
$ docker compose up -d web_run web_worker
# 2. 造一些演示数据：用户 alice / bob / carol，密码都是 redis123
$ docker compose exec web_run python /code/mysite/manage.py seed_demo
# 3. 打开 http://localhost:8000/blog/ ，另开一个终端观察 Redis 收到的每一条命令
$ docker compose exec redis redis-cli MONITOR
✓ 在两个 tag 之间看差异

想知道某个功能改了哪些代码：git diff step-02-redis-setup step-03-page-views -- Chapter03；想回到某一步：git checkout step-05-cache；列出所有 tag：git tag -l "step-*"。

不用 docker 也可以，本地跑测试的方式：

$ pip install -r Chapter03/requirements.txt psycopg[binary]
$ export DB_HOST=localhost DB_USER=postgres DB_PASSWORD=postgres DB_NAME=postgres
$ export REDIS_URL=redis://localhost:6379/0
$ cd Chapter03/mysite && python manage.py test blog   # 测试使用 Redis 的 db14/15，不会碰开发数据

数据结构核心命令在本项目中的用途
